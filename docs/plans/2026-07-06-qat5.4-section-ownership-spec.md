# CX-qat5.4 spec — section ownership via capability certs (the M2 demo bar)

Author: commonplace (Fable design/review; Sonnet implements Part A).
Inputs: CX-qat5 epic (M2 = THE DEMO BAR), qat5.3 local-write gate
(merged), qat5.2 browser identity (merged), existing capability layer
(`Trust.Capability` — `{:docs, [uuid]}` scopes, issue/delegate/
attenuates?, time-caveats enforced chain-wide by `VerifyChain`).

## 0. What the demo proves

X owns forest-path (a set of room docs) and edits it; Y's edit is
DENIED at the same verifier that gates federation imports; X delegates
an attenuated cert to Z and Z edits. First end-to-end production
exercise of the trust stack against browser-session writes.

## 1. Scope split — what jes's acceptance line contains

The epic's acceptance names four beats: own/edit, deny, delegate,
"revocation/supersession honored." The first three are pure
COMPOSITION of shipped machinery. The fourth is NOT — there is no
revocation mechanism anywhere in the trust layer today (verified:
zero matches for revoke/supersede under lib/commonplace/trust/).
Building revocation is new security-critical trust machinery and goes
DESIGN-FIRST (its own bead, plan-reviewed), not into this build.
Interim honesty: the demo's "revocation" beat runs on time-caveats
(short-lived delegation expires and the edit is denied `:expired`) —
real, enforced, already shipped — with true revocation records
following in the split bead.

## 2. Part A — the build (this spec, dispatchable)

### 2.1 `Commonplace.MUD.Sections` (small helper module)

- `issue_section(owner_ctx_or_audience, section_uuids, opts)` — wraps
  `Capability.issue/5` with `%{verbs: [:write], scope: {:docs,
  section_uuids}}` (NEVER `:execute` — the epic's security rider; the
  helper hard-rejects verb lists containing `:execute`, and the
  existing `check_no_code_doc_in_scope` heuristic still applies
  underneath). Persists the cert via the existing capability-store
  path the cap CLI uses (find it; reuse, don't invent).
- `delegate_section(owner_ctx, audience, subset_uuids, opts)` — wraps
  `Capability.delegate/5`; `attenuates?/2` must hold (subset scope,
  subset verbs, tighter-or-equal window). `opts[:ttl_seconds]` sets
  `not_after` (the demo's expiry beat uses a short one).
- Both take an explicit store argument (CommitStoreClient default) —
  the CX-ziye lesson: store-thread everything.

### 2.2 The acceptance test (THE deliverable)

`apps/commonplace/test/commonplace/mud/section_ownership_test.exs`,
modeled on local_write_gate_test.exs's named-store trio setup +
session_gate_smoke_test.exs's strict-mode pattern:

1. Setup: named store trio; strict trust config (accept_unsigned:
   false, node key trusted via phase-2.5); gate `:enforce`; three
   player identities X/Y/Z with keys (AgentKeys), a "forest-path"
   section of 2 room docs (MUD.Schemas or plain docs).
2. Root (node ctx) issues X a `[:write]` cert scoped to the section →
   X's signed write to room-1 LANDS.
3. Y (registered player, signed, NO cert) writes room-1 → DENIED
   `{:error, {:trust_rejected, _}}`, red event fires, nothing
   persisted.
4. X delegates room-1-only to Z → Z's write to room-1 LANDS; Z's
   write to room-2 DENIED (attenuated scope enforced).
5. Delegation with 1-second `not_after` → after expiry Z is DENIED
   `:expired` (the interim revocation beat).
6. Fence rider pin: X's `[:write]` section cert does NOT authorize
   `:execute` on a code doc in the section
   (`authorized_to_execute?/3` denies) — end-to-end this time, since
   CX-ziye fixed the named-store capability path.
7. Cross-surface beat: the SAME denied write via the browser action
   path (Chat.Actions-style or ViewActionDispatch with Y's signing
   context) surfaces the error tuple, not a crash — reuse
   session_gate_smoke_test's approach.

### 2.3 The live-demo runbook (docs, not code)

`docs/plans/2026-07-06-mud-demo-runbook.md`: a DEDICATED demo node
(separate `COMMONPLACE_DATA_DIR`, port other than 5199, localhost

NODE-GLOBAL application env today — that is WHY the demo gets its own

### 2.4 Constraints

DO NOT SPAWN SUBAGENTS. NEVER use run_in_background — all
verification foreground. No `bd`/.beads. No changes to trust.ex /
verify_chain.ex / commit_store.ex (composition only — if a gap forces
a substrate change, STOP and flag). No exposure work. Localhost only.
mix compile --warnings-as-errors clean; full core suite foreground.

## 3. Part B — split bead (design-first, NOT built here)

Revocation records: content-addressed `{:revocation, cap_cid}` signed
by an issuer on the revoked cert's proof path; stored alongside
capabilities; `VerifyChain` consults them per link → deny `:revoked`.
Supersession = revoke + reissue. Open design points for plan review:
revocation-store read cost per verify, offline/federated propagation
(revocations must travel with imports), and whether Wrinkle-H subtree
scopes (CX-tdkq.23) change the shape. Until it lands, short
`not_after` windows are the operational mitigation.
