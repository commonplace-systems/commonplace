# CX-qat5.2 + CX-41qg.4 spec — browser identity: invite → login → sessions sign as their player

Author: commonplace (Fable review/design; Sonnet implements). Inputs:
CX-qat5.2 bead, writer-identity plan W4 + Resolved §1/§3 (commonplace-plan
`docs/plans/2026-07-06-writer-identity-plan.md`), CX-88mw agent-key
custody pattern (`Commonplace.Crypto.AgentKeys`, `Presence.Identity.
register_agent/4` decisions D5/D6/D9), qat5.3 local-write gate (merged
735b9bd — this bead is what makes its strict mode usable by humans).

## 1. One sentence

Invite-based login mints a per-player Ed25519 key and binds the Phoenix
session to the pair `{SigningContext, hand}` at one resolution moment,
so every session-originated write is signed as that player and minted
under that session's own CRDT hand — extending the identity-from-ingress
discipline (resolve once at the door, thread by argument, never ambient)
to the web door.

## 2. Pieces

### 2.1 Player registration + invite minting (core lib)

New module `Commonplace.Invites` (apps/commonplace):

- `mint(player_name, root_uuid, store \\ CommitStoreClient, opts \\ [])`
  → `{:ok, %{identity_uuid, token, expires_at}}`.
  - Registers a `:usr` cold identity via the `register_agent/4` template
    (same shape, `:usr` kind — add `register_player/4` to
    `Presence.Identity` mirroring `register_agent/4`; creator-signs per
    D9, pubkey-to-doc is convenience per D6).
  - Mints the player keypair via `AgentKeys.ensure(identity_uuid,
    secret_store)` — custody in node-local SecretStore, never synced.
  - Mints a one-time login token: 32 random bytes, url-safe base64.
    **Custody:** the token is a bearer credential — store only its hash.
    SecretStore slot `"invite:" <> Base.encode64(:crypto.hash(:sha256,
    token))` → JSON `%{identity_uuid, expires_at}` (default TTL 7 days,
    `opts[:ttl_seconds]`). The raw token appears once in the return
    value and never at rest.
  - Idempotence NOT required across calls — minting twice = two invites
    for the same player; each token is single-use.
- `redeem(token, secret_store \\ SecretStore)` → `{:ok, identity_uuid}`
  | `{:error, :invalid | :expired}`. Single-use: delete the slot on
  successful redemption (delete-then-return; a second redeem of the
  same token gets `:invalid`). Expired tokens are deleted on contact.
- Friends-tier only: no self-serve signup, no rate limiting needed
  beyond the existing WriteRateLimit; minting happens via IEx/MCP/CLI by
  the operator.

### 2.2 Login endpoint + session binding (web)

- `GET /login/:token` (browser pipeline, new `SessionController`):
  - `Invites.redeem/1` → on success, `put_session(conn,
    :player_identity_uuid, uuid)` + `put_session(conn, :session_nonce,
    Base.encode64(:crypto.strong_rand_bytes(16)))`, then redirect `/wiki`
    with a "Logged in as {name}" flash. On failure: 403 page, no session
    change.
  - The session cookie carries ONLY `{identity_uuid, nonce}` — never key
    material. The private key stays in SecretStore custody; the
    SigningContext is re-resolved server-side per mount (see 2.3).
- `GET /logout` clears both keys.
- **W4 hand derivation (the design-doc rule, exactly):** `hand = lower
  53 bits of SHA-256(public_key <> nonce)` — implement as
  `Commonplace.WriterHand.for_session(public_key, nonce)`:
  `:binary.decode_unsigned(binary_part(:crypto.hash(:sha256, pub <>
  nonce), 0, 8)) |> Bitwise.band(0x1F_FFFF_FFFF_FFFF)`. This is the
  53-bit nonce-bearing family — do NOT reuse `for_doc/1`'s 32-bit
  space; the WriterHand moduledoc already documents the two-family
  split and the asymmetric deconfliction (nonce-bearing side re-derives
  on conflict; deterministic side never moves). Persisting the nonce in
  the session cookie is what makes the hand stable across remounts and
  LiveView reconnects (the design's "persisted in session state").

### 2.3 Session resolution helper (one seam, used by every LiveView)

`CommonplaceWebWeb.SessionIdentity.resolve(session)` →
`{:ok, %{signing_context: %SigningContext{}, hand: integer, signer_id:
String.t(), presence_path: String.t(), identity_uuid: String.t()}}` |
`:anonymous`.

- Reads `player_identity_uuid` + `session_nonce` from the session map
  (LiveView `mount/3` third arg / controller session).
- Loads the keypair from SecretStore via `AgentKeys` (add
  `AgentKeys.signing_context(identity_uuid, secret_store)` → `{:ok,
  %SigningContext{}}` | `{:error, :not_found}` if it doesn't already
  exist — check first).
- Derives `hand` per 2.2, `signer_id` via `Signing.signer_id/2`,
  `presence_path` from the identity doc's registered name (`"{name}.usr"`).
- Key missing/corrupt (e.g. SecretStore wiped) → `:anonymous`, never
  crash the mount.
- Resolve ONCE in `mount/3`, assign to the socket, thread by argument.
  No downstream re-derivation, no ambient lookups — CX-tdkq.32/CX-hoj
  discipline.

### 2.4 Adoption in LiveViews (this bead: chat; rider CX-nn4y: the rest)

- **ChatRoomLive**: replace `@placeholder_signer_id`/
  `@placeholder_presence_path` with `SessionIdentity.resolve/1` output
  when present; thread `signing_context:` into the action dispatch opts
  (the seam already exists — `Chat.Actions` accepts `:signing_context`).
  Anonymous sessions keep the current placeholder behavior (permissive
  workspace must keep working logged-out).
- **Session hand**: thread `hand` into chat writes as the
  reconstruction client_id. `Chat.Actions.load_messages_doc` picks the
  hand: `opts[:client_id]` when the caller passes one (the session
  hand), else the existing `WriterHand.for_doc_actor(uuid, signer_id)`
  fallback for hand-less callers (MCP/bots/bridge stay on the
  per-actor funnel until their own sessions carry hands).
- Outline/Wiki/Tree threading is CX-nn4y (separate build) — do NOT
  sweep them here; keep this diff reviewable.

### 2.5 Acceptance (from the bead, verbatim + pins)

1. `ambient_signed` telemetry fires ZERO times for logged-in
   session-originated chat writes (test: attach handler, post via
   action path with a resolved session, assert no event).
2. Logged-in chat posts land signed: commit.signer_id ==
   the player's signer_id (end-to-end LiveView test or action-level
   test with a resolved session context).
3. Login flow: mint → redeem → session bound; second redeem of the
   same token fails `:invalid`; expired token fails `:expired`; raw
   token never stored (assert SecretStore holds only the hash slot).
4. Hand stability: same session (same nonce) resolves the same hand
   across two `resolve/1` calls; two sessions of the same player (two
   nonces) get different hands; hand < 2^53.
5. Strict-mode smoke (the qat5.3 payoff): with `accept_unsigned:
   false` + pinned player identity + gate `:enforce`, a logged-in
   player's post LANDS and an anonymous post is REJECTED with the
   permission flash (reuse local_write_gate_test setup helpers).
6. Full corpus green; `mix compile --warnings-as-errors` clean.

## 3. Constraints

- DO NOT SPAWN SUBAGENTS.
- Localhost-only stays true — no exposure work, no TLS, no bind
  changes (CX-qat5.7 is hard-deferred; login is orthogonal to
  exposure).
- Never log or persist raw tokens/private keys; tokens hashed at rest.
- No new identity registries — `client_namespaces` stays the advisory
  binding index; nothing here reads hands for authorization.
- Don't touch the MCP/bot ingress paths (they already carry
  SigningContext where minted); don't churn CommandRouter.
- Commit style: single commit `CX-qat5.2 + CX-41qg.4: ...` on the
  worktree branch; run the affected app suites + full core suite
  before reporting done.
