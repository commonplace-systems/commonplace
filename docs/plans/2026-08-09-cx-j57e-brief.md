## 2. What happened, and why the existing guards missed it

CX-3an0 Stage B added a per-doc commit index maintained by a **private**
`commit_rows/1` choke in `commit_store.ex`. Two tripwires guard it:

- `doc_commit_index_test.exs` — asserts **exactly two** `{{:commit,` literals
  **in `commit_store.ex`**
- `local_write_gate_test.exs` pin 8 — sweeps callers of `commit_rows/1`,
  **also only in `commit_store.ex`**

⛔ **Both scan ONE FILE.** So the choke is airtight **inside** its module and
**undefended outside it**.

**Consequence, measured:** `projection/mixed_plane_history_fixture.ex` writes
commit rows directly (it must mint specific content-addressed ids to reproduce
a five-pin incident shape). After Stage B those rows had no index entries,
`all_commit_ids_for_doc` returned **empty** for that doc, the sweep found
nothing — and ⭐ **that fixture's POSITIVE CONTROL silently stopped tripping.**
Three projection tests went red and the cause was two modules away. Bisected:
**0 failures at `409a8b5^1`, 3 at `409a8b5`.** Interim fix @289894c writes the
index row by hand beside the commit row.

- `projection/mixed_plane_history_fixture.ex` — **legitimate raw writer**, must

  not a writer

⚠️ **Distinguish WRITES from READS.** `{{:commit, id}, commit}` in a `put` is a
writer; `{{:commit, id}, %{doc_uuid: ...}}` in a `select` reduce is a reader.
**A tripwire that flags reads will be muted by whoever hits it first**, which
is how a guard dies.
