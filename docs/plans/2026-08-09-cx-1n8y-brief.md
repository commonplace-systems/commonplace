## 2. The defect, at the line

`build_record/…` (~:265-284) folds over a doc's commits:

```elixir
{:ok, _bytes, _verdict} ->
  {hits, failures, attempted + 1}

other ->
  failure = %{"commit_id" => hex(commit_id), "reason" => inspect(other)}
  {hits, [failure | failures], attempted + 1}      # ← ALSO increments
```

⇒ **`attempted` increments on BOTH branches**, and is then stored as
`"commits_scanned"`. **So `commits_scanned` counts commits the sweep TRIED, not
commits that produced a verdict.**

⭐ **The tell, and it is exact:** because every commit is attempted,
`commits_scanned` **always equals** `commits_total` (`summarize/4`, ~:356-358:
`commits_total` is the length of all `commit_ids`). **Two numbers printed side
by side in the same summary line that can never disagree.** On the first live
run both read **25,995** while **4,719 commits (18.15%) produced no verdict**.

**What the summary omits entirely:** `skip_reasons` is a per-doc list and
**nothing totals it.** ⇒ Real coverage was **81.85%** and the line reads as a
complete answer over complete history.

⚠️ **And a percentage would still under-report the shape:** **78 documents were
FULLY unscanned** — every commit skipped — while 81 were partially skipped. **A
per-commit percentage lets a reader imagine partial visibility everywhere; the
truth was zero visibility on 78 docs.**

⚠️ Note `docs_scanned = total - length(skipped)` where `skipped` is *any doc
with ≥1 skip* — so that field is conservative in the right direction, but it
**conflates fully-unscanned with partially-skipped**, which are the two facts a
reader most needs separated.

**Not a scanner bug:** every skip was `{:unknown, {:conflicted, …}}` — a
projection/trust verdict. Those commits declined to yield state, and
`MixedPlane.scan/1` runs on reconstructed state. ⇒ **It is a coverage limit the
scanner does not surface.** Do not try to make conflicted commits project.
