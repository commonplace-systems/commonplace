# CX-qat5.3 spec — the third `Trust.authorized?` call site: gating local writes

**Status: SPEC FOR JES REVIEW — do not build until approved** (boss #5651:
security-critical + a scope decision jes wants eyes on). Author: commonplace
(Fable). Design inputs: CX-qat5.1 recon (browser write-path inventory),
commonplace-plan's MUD assessment (2026-07-06-multiplayer-mud-assessment.md),
trust.ex code reality at main `40b2813`.

## 1. What this adds, in one sentence

Every locally-created commit passes `Trust.authorized?(commit, :write,
{:doc, doc_uuid})` before persistence — the same verifier that already
gates federation imports and code execution — turning the browser (and
every other local ingress) from an ungated door into the third gated
call-site family.

## 2. The scope decision jes needs to make (THE decision)

The CX-qat5.1 recon found that all browser writes converge on one terminal
seam: `CommitStore`'s create path (`do_write_commit` for the legacy verbs,
`put_built_commit` for the hoisted CAS path). Gating THERE is the only
placement that is structurally no-bypass — but that seam serves **all local
ingress**, not just browsers:

| Ingress | What gating means for it |
|---|---|
| Browser LiveViews (wiki/chat/outline/tree) | The target: session writes judged by the verifier. |
| MCP agent tools (write/loom_send/mud_send/…) | Agent writes judged the same way — desirable, consistent with agents-as-principals. |
| CLI one-shots | Judged as whatever they sign as (user key or unsigned). |
| GitBridge inbound mints | Already bridge-signed; the gate closes the loop the CX-b0ow.2 moduledoc promised ("the qat5.3 chokepoint will gate this seam"). |
| System writers (snapshotter, merger, presence heartbeats, reflog, TickBot) | Node-signed system kinds pass via the phase-2.5 local-node-trust fold-in; **presence/reflog/chat-compute writes are NOT system-kind** — they sign as whatever context they carry (today: nothing/placeholder). |

**Alternative rejected:** a browser-only gate (in the LiveView layer or
CommandRouter) would miss the recon's three side-doors (presence heartbeat
GenServer, wiki's two-commit create, fork's root-schema attach) and would
be a fourth bespoke gate instead of the third call-site *family*. The
whole-local-ingress scope is what the trust arc's design names as "local
ingress"; the blast radius is broader but the mechanism is honest.

**What makes this safe to ship:** in the DEFAULT permissive config
(`accept_unsigned: true`, no pinned identities), `authorized?` returns
`:ok` for everything — the gate is a **no-op for jes's current workspace**.
Enforcement only begins when a workspace flips to strict
(`accept_unsigned: false`) or pins identities. The gate ships dormant;
the MUD demo (qat5.4) turns it on deliberately.

## 3. Placement and mechanics

- **Where:** `CommitStore.do_write_commit/7` and the
  `{:put_built_commit, …}` handler, immediately after the commit is built
  and signed, before `put_multi` — mirroring `import_validation`'s
  `trust_check` (the commit is complete, signature attached, id final).
  Two clauses, one private helper (`local_write_check/2`), same error
  taxonomy as the import gate: `{:error, {:trust_rejected, reason}}`.
- **Skip for system kinds where the import gate also has carve-outs:**
  none needed — node-signed `:snapshot`/`:merge` commits pass because the
  node's own key is auto-trusted (phase 2.5 `with_local_node_trust`).
  Genesis commits (synthetic, unsigned, empty) must be exempted the same
  way the import path exempts them — explicit clause.
- **The CAS/hoisted path caveat:** `put_built_commit` receives a
  caller-built commit; the gate runs server-side on the built commit —
  no TOCTOU (the CAS handler is the serialization point).
- **Retry semantics:** none — a trust rejection is not a `:parent_moved`;
  the caller-side CAS loop must NOT retry on `{:error, {:trust_rejected,_}}`
  (surface immediately; add the clause to `CommitStoreClient`'s
  `attempt_write`).
- **Failure surfacing:** rejected browser writes → the write helper returns
  the error; each LiveView shows a flash ("You don't have permission to
  edit this") — user-visible, never silent. Red event
  `{:trust, :local_write_denied, %{doc_uuid, signer, reason}}` on the doc's
  topic (the observability the MUD demo narrates). MCP writes return the
  error tuple through the tool result.
- **Telemetry:** `[:commonplace, :commit, :rejected, :local_trust]`
  mirroring the import-side rejection events, plus a counter for
  permissive-mode would-have-denied dry-run (see §5).

## 4. Dependencies and ordering

- **Needs qat5.2 first for strict mode to be usable by humans** (sessions
  must sign as real players or strict mode bricks the browser), but the
  gate itself can land earlier since it's a no-op in permissive mode.
  Recommended order: land qat5.2 (real session identities) → land this →
  flip the MUD workspace to strict in qat5.4's demo.
- **No-bypass sweep (part of this bead):** assert no write path reaches
  CubDB commit rows except through the two gated handlers + import — a
  code-audit note plus a regression test that greps/enumerates
  `put_multi` call sites writing `{:commit, _}` keys.
- **The write/execute fence** (epic security rider): unchanged — Gate B
  and CX-tdkq.28 already enforce; this bead adds a pin test
  (player-signed `:write` cert cannot execute a code doc).

## 5. Rollout safety — the dry-run knob

Because this gate touches every local write, ship with a three-position
config: `:off` (no check — emergency escape hatch), `:dry_run`
(check, log + telemetry on would-deny, never reject), `:enforce`
(reject). Default `:dry_run` in dev, `:enforce` follows the workspace's
strict flag. This gives jes a zero-risk observation window on the real
workspace before any enforcement anywhere.

## 6. Test pins

1. Permissive default: all existing suites green with the gate live
   (the no-op property — the whole CI corpus is the test).
2. Strict + unsigned browser write → rejected, flash shown, red event,
   nothing persisted, CAS loop does not retry.
3. Strict + player-signed write with pinned identity → lands.
4. Strict + system snapshot/merge (node-signed) → lands (phase-2.5).
5. Genesis exemption.
6. Dry-run: would-deny logged + telemetry, write still lands.
7. Fence pin: `:write`-certed player cannot land on a code-doc execute path
   (existing Gate B behavior, asserted end-to-end from a session write).
8. No-bypass: the commit-row-write-site enumeration test.
